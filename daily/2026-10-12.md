## 📄 学术论文研究动态

- **Opera：面向长程编程 Agent 的言语批评框架**：长程编程 Agent 需要及时纠错，但反馈若误判进行中的工作或未触及根因，反而有害。现有 critic 只评估轨迹并生成反馈，很少追踪反馈送达后发生了什么。Opera 把每次纠正当作一条持续存在的 note，一直跟踪到被诊断的问题真正解决：通过周期性触发与事件驱动触发决定何时复查，用带类型的 operator 诊断问题，在交付前依据可见证据审计反馈，并追踪 Agent 后续动作以区分「表面服从」与「真正解决」。在 Terminal-Bench 2.1、SWE-Bench Pro 子集与 DeepSWE v1.1 上，作为测试时 critic 让无 critic 的 Agent 解决率分别提升最多 12.4、15.0、8.9 个百分点，覆盖四个策略模型，并在三个基准上取得竞争性 critic 基线中最高的平均解决率；策略模型自我批评时同样有效。除推理外，Opera 引导的 rollout 近似 on-policy 训练数据，用它微调 Qwen3.5-9B 在留出 SWE-Bench Pro 仓库上解决率提升 10.2 个百分点且推理时不需要 critic，切换 harness（如 Openhands 到其他）后性能仍保持。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.33987)

- **Skill Constellations：追踪 GitHub 上 Agent Skills 的供应链**：Agent skills 是 SKILL.md 指令与脚本，Claude Code、Codex 等编程 Agent 会以用户权限执行它们。开发者通过在仓库间复制来分享 skill，于是形成了一个没有 registry、没有版本、没有 provenance 的软件供应链，导致被复制 skill 的来源、安全修复的覆盖范围、以及哪些仓库值得审查都无从得知。此前只记录某一时刻哪些仓库持有 skill 的研究，无法揭示谁抄了谁。该工作贡献了首个带时间戳的 agent skill 复制网络，基于 GitSkills 中每个 SKILL.md 的 git 历史构建，覆盖 GitHub 上 2,193,119 次 skill 采用，并附带交互式查看器。结论是少数仓库是几乎所有复制的源头，且 GitHub star 无法识别它们；skill 副本几乎从不随源更新，源头的修复很少传导过去。作者拟合了「谁从谁复制」的模型用于审计排序：审查其排名最高的 100 个仓库可阻止 14.9% 后续高风险 skill 采用，而 100 个最高 star 仓库只有 0.5%。平台应分发带版本的引用而非副本。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2610.11169)

- **MiMo-V2.6：把强化学习扩展到自我改进**：该报告介绍 MiMo-V2.6 系列，一个 omni-modal 家族，通过扩展 RL 算力推进模型智能前沿。RL 之前先在广泛的多模态语料上做 mid-training 以提供充足探索空间，并在预训练 hybrid-SWA 架构上构建基础设施支撑后续扩展。RL 算力沿三个维度扩展：更大 batch 与更高吞吐，异步训练每步消耗 1,568 个样本、2.7-3.7B tokens，上下文长度最高 1M；更丰富复杂的环境，在混合 agent harness 下覆盖代码、通用、视觉与网络域；更多 grader 算力，通过 groupwise agentic grading 为长程任务提供更准确奖励信号，并引导模型给出更短、更省 token 的解。为在大规模下保持稳定，冻结 MoE router 并建立多层防御对抗 reward hacking。还构建了混合任务 agentic RL 基础设施，包括统一轨迹表示、高并发多框架 rollout、控制面与数据面解耦、训练推理一致性。训练动态、RL 环境与 RL 框架均已开源。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2610.11959)

- **Station：AI Agent 能否做开放式科学发现**：近期 AI 系统在给定明确指标的科学发现上进展迅速，但能否自主开展开放式科学发现仍不清楚。作者在 Station 这一开放世界环境中考察该能力，环境中多个 Agent 模拟一个科学生态系统。为应对开放式任务的挑战，为 Station 增加两个机制：Supervisor 机制与周期性 Meta Reflection，鼓励在缺乏中间指标时仍持续探索。开放式任务取自 ICLR 三篇近期 oral 论文，只给 Agent 每篇论文研究的核心问题，隐去论文结果并禁用网络访问，再测量 Agent 重新发现多少被拆分为独立判据的原始发现。结果 Station 平均重新发现 62.7% 的判据，而 Codex Multiagent-v2 为 15.4%，AI Scientist-v2 为 14.4-20.6%。消融与行为分析显示两个机制同时加入可提升研究覆盖度与连续性。在没有 oracle 论文的两个开放式任务上，Agent 的部分发现与知识截止后研究者报告的发现高度吻合。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2610.08927)

- **The Lattice of Transition Laws：用 corruption lattice 统一扩散与自回归的解码调度**：扩散与自回归长期被视为两类不同的生成模型，前者擅长连续场、后者擅长离散 token，近期混合工作各自把解码调度固定为设计选择。本文提出：能否在固定步数解码前就预测某个模型解码调度的性能。作者把扩散、AR 及介于两者之间的模型描述为同一 corruption lattice 上的路径，并把调度代价定义为并行步骤所丢弃的依赖。该代价表明，零代价调度的最少步数由数据几何决定，对 token 和连续场同样成立。具体而言，对在图上马尔可夫、并沿其路径依赖的数据，最少步数等于图的 treedepth，它与序列长度成对数、与网格边长成线性。步数少于 treedepth 时，任何调度都要付出正代价，而该代价的排序可在解码前用从预训练权重估计的成对依赖核预测。在文本、图像、视频生成上，作者验证了关于不同调度在不同指标与基准下排序的大部分预测。这为未来 AR、扩散及中间形态模型的解码提供了设计原则。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2610.11216)

- **Memento 3：通过反思式规则手册实现基于模型的递归自我改进**：在不熟悉环境中行动要求 Agent 推断世界如何运作，并随新证据修正理解，但有限观测可能支撑多个世界模型，它们能解释过去交互却在未见状态上预测不同结果。Memento 3 让冻结的 LLM Agent 通过外部记忆持续学习显式世界模型：Agent 维护一本自然语言规则手册作为持久语义记忆，记录关于环境动态的可修正假设，同时把未知方面保持为未指定，再把规则手册编译成可执行代码用于预测与规划。通过观测、反思、规则修订、编译与验证的持续循环，Agent 用预测误差同时改进规则手册与其代码；只有当 LLM 判断更新后的代码忠实于规则手册、且 cell-exact replay 能复现观测到的状态转移时，更新才被接受。作者把这一过程作为通向递归自我改进的基于模型的路径来研究：Agent 自主探索、修订世界模型，并用经过验证的更新指导后续交互与学习，而底层 LLM 保持固定。群体扩展并行维护多个世界模型，共享交互证据并用其预测引导探索。在 ARC-AGI-3 上，单模型 Agent 通关全部 25 个公开游戏的所有关卡。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2610.11794)

- **Mara Chain：把失败候选变成自我演化的垫脚石**：优化已部署 AI 系统越来越等同于编辑 prompt、skill、harness 与代码，而非模型权重。现有方法通常用 propose-evaluate-select 流程优化这些产物，只保留满足接受标准的候选，但作者分析发现被丢弃的候选往往包含后续优化所需的关键信息，丢弃它们会让后续提议重复踩同一批失败模式。Mara Chain 把被拒绝的候选保留下来，并用跨先前尝试累积的证据迭代精炼，每条精炼链限制固定深度，并用 Pareto 过滤的 Top-N 选择约束候选池。在 AppWorld skill 优化、TerminalBench 2.1 harness 优化与 MuSiQue 检索流水线优化上，Mara Chain 用更少 rollout 取得更大任务性能增益：AppWorld 上相对性能比 GEPA、ACE、SkillOpt-Lite 高出最多 20.5%，达到目标分数所需 rollout 比 GEPA 少 65.5%；TerminalBench 2.1 上通过率分别比 AHE 和 Meta-Harness 高 20.2 与 22.5 个百分点；MuSiQue 上 test nDCG@10 与 Recall@10 比手写检索流水线提升 0.104 与 0.131。
