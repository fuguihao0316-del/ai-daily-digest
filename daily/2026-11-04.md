- **Anthropic 为 Messages API 推出 Message Threads，长对话首 token 延迟降 35%**：Anthropic 在 Messages API 中上线 Message Threads。过去每一轮对话都要把完整上下文重新发送一遍，现在 agent 只传输发生变化的部分。官方数据是：在 50 万到 100 万 token 的请求区间，首 token 时间下降约 35%。这对长上下文 agent 的成本结构影响直接：重复传输的 token 既消耗带宽也消耗计费额度，改为增量传输后，多轮长任务的单轮边际成本显著下降。对开发者的实际约束是需要在客户端维护线程状态、处理增量与全量的切换逻辑，已有基于全量重发的实现需要改造。考虑到当前 agent 产品的上下文普遍在向百万 token 量级推进，这类协议层优化会比模型升级更早体现在用户体验上。

## 📄 学术论文研究动态

- **IdeaTaste 基准：LLM 的科研品味仅达人类 18%**：研究提出 IdeaTaste，以 2025 年冻结的文献快照为输入，让 LLM 撰写研究提案，再与同一社区 2026 年实际发表的论文比对。实验覆盖六款当代语言模型、四个研究领域（从成熟到新兴），共评估逾 9 万份提案。结果显示，LLM 智能体在引用匹配上仅达人类约 26%，在想法匹配上仅 18%；它们能像社区一样多样化引用、并采纳该社区的任务与方法，却很少落到具体的实现路径与研究计划上。更丰富的领域上下文和更大的群体规模都未能显著缩小差距。盲审专家评审中，AI 提案在呈现形式上落后最少，在预期成功率上落后最多；而那些没有任何人类论文共享其想法的提案表现最差，说明是方向本身偏弱，而非人类忽视了机会。结论是 AI 科研品味的主要瓶颈不在找方向，而在把方向转成具体方法。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.03424)

- **StreamDuo：解说员加研究智能体，实现跨游戏直播解说**：流式视频 LLM 已能实时解说游戏，但训练与测试都在同一款游戏上。该工作研究跨游戏流式解说，发现现有解说模型能迁移时间节奏，却无法迁移游戏世界知识。StreamDuo 将一个可训练解说员与一个冻结的研究智能体配对，后者读取当前所玩游戏的 wiki。当解说员遇到叫不出名字的内容时，发送当前帧，研究智能体在两秒后返回若干 wiki 条目，直播继续进行。训练只针对解说员、只用一款游戏、分两阶段：信息增益标签教它只在答案有助于复述人类解说词时才发问；来自能看到理想答案的自身副本的 on-policy 自蒸馏教它使用带噪答案。在 Baldur's Gate 3 上训练、在十款未见游戏上测试，实体召回从 Proact-VL 的 0.082 提升到 0.116，源游戏泄漏从 9.9% 降到 1.0%，并在流式模型中取得最佳时间节奏与最高评审活跃度、整体质量。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.01120)

- **History Forcing：为长时程视频世界模型蒸馏历史依赖的续写**：少步自回归视频扩散生成高效，但长rollout 一致性难保，主体或场景离开视野后再次出现时尤甚。现有蒸馏方法未充分利用更丰富的历史信息约束学生当前预测。History Forcing 提出统一 on-policy 蒸馏框架，用教师在有、无信息性历史上下文下预测的残差来解耦该监督信号；历史上下文可来自漂移更小的早期生成块，或来自保持场景可见的固定视角教师 rollout。残差经加权后加到用于蒸馏的 score 或 velocity 预测上，形成修正目标，使学生对齐后把长程历史约束注入自回归生成。该方法在 1.3B 模型中达 SOTA，15 秒视频生成 VBench 质量分 85.07，60 秒生成 VBench-Long 综合分 79.82；视野外世界建模评测显示场景演化更合理、一致性更高。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.02782)

- **DR Pixel：以页面图像为唯一检索与推理单元的深度研究智能体**：科学论文的表格、图、公式承载大量信息，但现有深度研究智能体通常把论文降维成 OCR 文本。该工作提出页面原生深度研究：直接对渲染后的文档页面图像做检索与推理。DR Pixel 是首个开源端到端多模态深度研究智能体，以页面图像为唯一检索与推理单元，语料规模 106 万页。为评测该设定，构建 DRPixelBench，要求对文本、图、表、公式联合推理。出人意料的是，未经训练的页面原生方案在 GPT-5.4、Gemini-3.5-Flash、Qwen3.6-27B 等模型上已优于 OCR 基线，且工具调用更少。训练方面，教师轨迹噪声大，混有冗余与失败尝试，为此提出反事实信用重加权，按各推理与动作步骤对最终答案的反事实贡献赋权。训练后 DRPixelBench 检索召回提升约 15 点、最终准确率提升逾 10 点，并在四个现有基准上优于未训练基线。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.03097)

- **LeanGuard：用 Lean4 形式化策略为工具调用智能体加护栏**：工具调用型语言模型智能体常执行领域策略禁止的动作。LeanGuard 是一个运行时，在每次工具调用到达环境之前，用 Lean4 编写的策略逐条检查。策略把状态谓词与作用于执行历史的作用域过去时态算子结合，求值 fail-closed，判定过程被证明与 LeanLTL 语义等价。被拒调用有两种纠正方式：带反馈时，智能体收到被违反的规则与提示；证明引导修复时，Lean 元编程搜索一个保持用户意图的邻近调用，并证明策略允许它，全程不依赖模型。在 Tau-Bench 上，五个 Qwen 模型（0.8B–27B）的无护栏智能体至少执行了 33 次 Lean 策略禁止的调用，LeanGuard 一次都没有；带反馈时任务成功率无显著变化。在 DTap 上，LeanGuard 把直接提示注入成功率从 57.9% 降到 5.9%；电信场景中良性任务本不需写操作，良性成功率不变。对 252 次由参数值导致的拒绝重放，修复在 88 次中证明了可接受的修改，中位耗时 2 毫秒。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.02332)

- **SWE-Trail：用历史引导编码智能体的轨迹采集**：编码智能体通过长序列的探索、编辑、验证解决仓库问题，这些轨迹日益被用作后训练数据，采集方式决定模型学到什么。常见做法是对每个问题独立采样多条轨迹再筛选，但独立采样越多，后续轨迹越冗余，而早期轨迹本可指导后续采集投入何处。把历史作为建议暴露给智能体虽自然，却会造成训练-测试不匹配：测试时没有建议。SWE-Trail 主张历史只用于引导采集投入的位置，生成内容仍由智能体自行决定。新一轮 rollout 中，SWE-Trail 用历史定位一个值得追加采集努力的状态，智能体从常规上下文提出候选下一步动作，SWE-Trail 从同一检查点短暂执行这些动作以决定走哪条路，历史始终不进智能体上下文。评测以所产轨迹训练学生模型为准，实验基于从 Ling-3.0-flash 初始化的 124B 学生模型。
