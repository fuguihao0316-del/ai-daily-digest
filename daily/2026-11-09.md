## 🗞 AI 行业动态

- **AI 审计模型能抓出多数 Agent 越界行为，但误报淹没复核者**：Anthropic 研究员 Andy Hall 主导的一项研究测试了用 AI 模型审计其他 AI Agent 的运行日志，结果显示 GPT-5 能识别出约 98% 的 reward hacking（奖励作弊）案例，说明模型对同类异常行为的识别能力已相当可观。但研究同时发现一个关键瓶颈：搜索调得越彻底、覆盖越全面，误报数量就越是急剧上升，复核者不得不逐条人工排查大量假警报，实际可用性大打折扣。结论是这类 AI 审计目前还不足以支撑可靠的安全检查流程——高召回率与低误报率之间的权衡尚未解决，若要把审计模型嵌入生产环境的 Agent 监控，仍需配套的告警分级与人工复核机制，否则安全团队会被噪声拖垮。
  - 重要性：★★★★★ / 5
  - 来源：[The Decoder](https://the-decoder.com/ai-auditors-catch-most-agent-misbehavior-but-flood-reviewers-with-false-alarms-new-study-finds/)

- **开源与闭源模型在网络攻击能力上的差距持续收窄**：Vals AI 的基准测试显示，OpenAI 的 GPT-6 Sol Daybreak 在模拟企业网络环境中达成 80.8% 的攻击目标，而开源权重模型 DeepSeek V4.1 Flash 以仅约十分之一的成本达到 72.8%。这一对比的意义在于：过去闭源前沿模型的安全优势部分建立在能力不公开、访问受限之上，而开源权重模型一旦具备接近的攻击能力，就无法再通过许可或 API 管控来限制其使用。分析人士据此判断，防守方利用能力差距构建检测与防御的时间窗口正在快速缩小。对安全团队而言，这意味着威胁建模必须把低成本、可本地部署的开源模型纳入假设，而不能只盯住少数几家闭源厂商的旗舰模型。

- **Google 发布 Elephant-Goldfish 插件，让编码 Agent 先写规格再写代码**：Google 推出名为 Elephant-Goldfish 的模型插件，思路是「规格优先」：编码 Agent 先起草规格说明，随后经过 5 个零上下文（zero-context）的评审阶段，全部通过后才开始生成代码。所谓零上下文评审，指每个评审环节不共享前序对话与实现细节，以独立视角检查规格中的歧义、遗漏与矛盾，从而避免单一上下文中的自我确认偏差。这一设计针对的是编码 Agent 常见的失败模式——在需求模糊时径直写出看似合理但方向错误的代码。对使用编码 Agent 的团队来说，该插件提供了一种可复用的工程约束：把返工成本前移到规格阶段，而不是留到代码评审或测试环节才发现问题。
  - 重要性：★★★★★ / 5
  - 来源：[MarkTechPost](https://www.marktechpost.com/2026/11/08/google-elephant-goldfish-model-plugin-spec-review-coding-agents/)

- **Alibaba Co-Design Bench：真实场景下编码 Agent 近四分之三任务仍需人工收尾**：阿里巴巴发布新的编码 Agent 基准 Co-Design Bench，特点是测试用例取自真实用户请求中此前已让 Agent 失败过的案例，而非人工构造的题目。结果显示，表现最好的 GPT-6 Astra 仅完整解决 26.4% 的任务，意味着接近四分之三的任务仍需人工清理与修补；而在旧有基准上，同样的模型得分超过 99%。这一落差直指当前编码 Agent 评测体系的核心问题：饱和的基准已无法区分模型能力，真实世界的模糊需求、隐含约束与多轮修改才是难点所在。对采购或部署编码 Agent 的团队而言，厂商标称的基准分数参考价值有限，应改用贴近自身业务的历史失败案例做验收测试。
  - 重要性：★★★★☆ / 5

- **Buoyant 开源 Kinference：面向 Kubernetes 与 vLLM 的推理控制平面**：Buoyant 发布 Kinference，一个采用 Apache 2.0 许可的推理控制平面，用于在 Kubernetes 上调度 vLLM 推理服务。核心能力包括声明式路由策略、KV-cache 感知的负载均衡，以及按租户粒度的指标采集。其中 KV-cache 感知的负载均衡是关键差异点：传统负载均衡按请求数或连接数分发，容易把请求打到缓存未命中的实例上，导致重复预填充、首 token 延迟升高；按缓存命中情况路由则能显著降低这一开销。Buoyant 自测数据显示中位 TTFT（首 token 延迟）降低 95%。对自建推理集群的团队来说，这类控制平面填补了 vLLM 原生调度与生产级多租户运维之间的空白，值得在压测环境中验证其收益是否可复现。

## 📄 学术论文研究动态

- **Tools Need Not Speak in Text：用隐上下文压缩替代工具文本输出**：清华 THU-Agent 团队提出 Coca-Cola，把 LLM agent 收到的工具返回结果压缩成 latent token 并直接嵌入输入嵌入空间，不再以显式文本 token 追加到上下文；配套的 Action-Preserving Training 对齐压缩前后 agent 的下一动作分布，使 latent token 保留决策关键信息。在四个 QA 基准、两个模型家族上的 web-search agent 实验中，token 消耗降低 70.01%-89.24%，端到端运行时间降低 24.45%-55.97%，任务表现同时提升。这挑战了「工具观测必须以文本形式进入上下文」的默认假设，对长程多步 agent 的上下文预算与延迟优化是一条可直接复用的路径，代码已开源于 THU-Agent/Coca-cola。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.06500)

- **StepX-OPD：把多教师能力蒸馏与少步采样合并为单阶段**：可部署的 text-to-image 扩散模型需同时具备指令跟随、文字渲染、人类偏好与少步采样能力，而现有流程分两阶段：先用多教师 on-policy 蒸馏整合能力，再把全步模型作为固定教师做步数蒸馏。StepX-OPD 将两者合并，让学生模型在自身 rollout 访问到的状态上接受冻结专家监督，并针对 KL 分解中噪声端附近速度失配最重的问题回归低噪声段速度；作者还发现能力整合会让模型在未要求文字的 prompt 上把提示词写进图像，并给出降低该现象的变体。在 SD3.5-Medium 与 FLUX.1-dev 上，其四步方法归一化平均分最高并超过四十步 Flow-OPD，SD3.5-Medium 上训练 GPU 小时比顺序式 DiffusionOPD 少约 37%。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.04386)

- **SwarmEvolve：用潜空间通信的 agent 群体做进化式程序搜索**：LLM 引导的进化搜索每轮都要生成冗长文本思维链以维持种群多样性，速度受限。SwarmEvolve 让每轮数百个低成本 agent 组成群体，在潜空间推理而不解码为文本，通过传递 KV cache 共享信息；每个群体从不同角度研究问题，新颖性过滤器直接以隐藏状态向量距离保留最独特的想法，总结 agent 接收全体成员合并的 KV cache 使想法在潜空间自然交叉。在数学发现与科学计算的 21 个问题上，SwarmEvolve 平均分最高，达到其他 SOTA 框架需 60 分钟才能取得的最佳分数中位仅需 3 至 8 分钟；在若干问题上，Qwen3 8B 驱动的版本改进了 AlphaEvolve 用前沿 LLM 首次找到的解。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.08483)

- **OpenFrontiers：开放研究问题语料库加科学再发现基准**：该资源把结构化开放研究问题语料与数学领域近期已解决问题的回溯基准结合。语料记录 12,151 个问题的陈述、背景与进展；基准含 200 道题，其中 110 道于 2026 年解决、90 道仍开放，每题配经自动化探针与两次独立评审检查的 Lean 4 陈述，HQ-50 子集按质量分进一步筛选。评测协议在隔离沙箱中用两个独立检查器评分，设闭卷、冻结检索与实时联网三种条件。七个 LLM agent 在标准化预算下跑 HQ-50，闭卷再发现极罕见，40 道已解题中最多解出 7 道，联网成功则多反映检索到已发表解答。这为区分「真推理」与「检索命中」提供了可复现的评测底座。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2610.37739)

- **TB-MathModel：首个 agentic 且可验证的数学建模基准**：数学建模要把开放现实问题转化为假设、模型、求解与可辩护建议，答案须既接近可信参考又物理可行，而现有基准要么只评求解片段，要么用 LLM judge 评报告。TB-MathModel 覆盖 2023-2025 年 18 道真实 CUMCM 与 MCM 赛题，每题在容器化终端中提供原始题面、官方附件与图表，agent 返回单个 JSON 产物，按最终问题的数值核心对照 Outstanding 论文复现评分。两项设计值得注意：方向感知的单侧评分不惩罚超过锚点，两层可行性验证由六类可判定不变量程序门与 624 条 Lean 4 义务组成，不可行答案直接归零；每题对照多篇人类优秀论文而非单篇。七个多模态系统三次种子下最强仅达多参考 O-Eval 64.58%。
  - 重要性：★★★★☆ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.08237)

- **Muir：按敏感度分配门控的线性注意力与匹配滤波读出**：线性注意力把上下文压缩为固定大小 KV 状态，Gated DeltaNet-2 用通道级衰减与解耦全秩擦写门推广 delta 规则。作者指出状态更新对擦除的敏感度远低于写入：key 激活与单位归一化把 key 能量集中到稀疏通道，而 value 写入缩放所有通道，因此擦除门可用更低秩参数化；同时慢衰减状态行范数远大于快行，主导无权重读出。Muir 据此把所有门融合为敏感度分配的低秩投影，用匹配滤波读出门重新加权状态行，并把省下的参数投入更宽前馈网络；针对大 chunk 下分块算法数值不稳，设计了稳定并行更新。166M-1.34B 规模上困惑度比 GDN-2 低 1.8-2.0%、比 Transformer 低 2.5-3.6%，常识准确率最高提升 1.9 分。
  - 重要性：★★★★☆ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.08376)

- **SAE Interprets MoE：专家呈现人类可读的细粒度分工**：MoE 每个 token 只路由到少数专家，但单个专家负责什么仍无定论，既有分析多在领域标注语料上统计被选中频率，分类体系预先固定且只记录选择而非贡献。该工作在特征空间研究专门化：在 MoE 层输出上训练稀疏自编码器，由于层输出是专家输出的路由加权和且 SAE 编码器为仿射，每个 latent 的预激活可精确分解到各专家，聚合语料后得到每个专家主导的 latent 集合。在 Qwen3-30B-A3B 的第 4、30、46 层，贡献远比门控集中，多数 latent 仅有一到两个主导专家，主导集合重叠集中于少数专家对；自动解释显示粗粒度领域之下还有更细分工，如 Java 与前端 web 代码分属不同专家、几何与算术多项式分属不同专家。
