## 📄 学术论文研究动态

- **Iris-Z 用单一生成模型统一单目几何任务**：研究团队提出 Iris-Z，将外观与几何生成合并进同一个骨干网络，用一组权重同时完成图像生成及其深度、从照片估计深度、以及按给定深度绘制图像三类任务。作者主张视觉智能应像语言模型一样走统一架构加规模化路线，而非继续堆叠任务专用设计。在既有深度基准上，达到足够规模后其表现超过专用 SOTA 模型，同时保留原骨干的生成能力且不引入专用层。团队向社区发布两个模型。这一结果对深度估计、3D 感知与生成式视觉的架构选型有直接参考价值，也提供了「bitter lesson 适用于视觉」的一个实证样本。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.16010)

- **V-JEPA-LM 让视频语言模型真正读取动态而非静态文本对齐特征**：作者指出，现有视频语言模型把 V-JEPA 类世界模型编码器接上语言模型后，模型只学会检索字幕中提到的少数属性，编码器携带的动态信息被浪费：在相同样本上，线性探针从冻结 V-JEPA 特征读取速度的准确率为 87%，而 VLM 仅相当于随机猜测。研究发现动态信息存在于预测式编码器跨视频共享的子空间中，而 SigLIP 这类逐帧文本对齐编码器不具备该共享成分。据此构建反事实监督，用像素变换生成答案均衡的变体，让语言模型必须读取变化本身。仅单阶段训练、4.53M 公开样本、每帧 32 个视觉 token，1B 至 8B 的 V-JEPA-LM 在十一项视频基准上领先各规模同级模型，4B 版本得 72.1 分，最强开源 4B 为 61.1，最强开源 8B 为 64.8。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.17831)

- **Re-Search 用二十问游戏拆解 LLM 的研究构思过程**：该工作把研究构思改造成「二十问」形式：只给出一篇已发表论文的研究问题，模型需通过提出是/否问题重新发现论文核心思想。基准由 200 篇 ICML 2026 论文构建，可追踪模型想法在二元 oracle 反馈下如何演化，从而把构思与执行分离。测试六个近期 LLM 发现，几乎所有进展都发生在 100 个问题中的前 30 个，此后多数模型进入平台期。对候选问题与假设空间做受控干预后，作者判定瓶颈在生成而非判断：模型能识别好想法或好问题，却常常无法自行产出。构思轨迹显示失败模式为过度利用单一方向或过度探索过多方向。作者据此提出对自动研究系统的设计原则：引入外部来源的想法与问题，可能比提升单模型生成能力更有效。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.14487)

- **SWE-CoWork 把编码智能体放进模拟工程组织考核**：新基准包含 101 个开发任务，覆盖 101 个真实代码仓库、11 种编程语言和 12 个应用领域。每个任务把智能体置于拥有 26 位同事的模拟工程组织中，同事有各自职责、有限知识和受控协作行为。智能体需从一次简短交接出发，向同事与工作记录追回分散的需求、调和冲突证据，并实现通过私有可执行测试的改动。评测十一个模型后发现部分实现与完整交付之间存在巨大鸿沟：两个领先模型满足约 63% 的 fail-to-pass 测试，但完成的任务不足 8%。提前提供完整需求可为 Seed Evolving 与 GPT-6 Astra 提升约 16 个百分点的 F2P，却未改变完整任务成功率。轨迹分析显示 Claude-Opus-5.5 平均把 93% 的首次提问指向被查询卡片的负责人，但仅获得 64% 的同事持有需求，31% 的需求被报告为已完成却并不成立。
  - 重要性：★★★★★ / 5
  - 来源：[arXiv](https://arxiv.org/abs/2611.20218v1)

- **LuthorSQL 用 7B 单次前向模型为慢速 LLM 智能体做 System 1 闸门**：前沿 LLM 智能体查库虽准，但每次调用托管模型既慢又贵，还把敏感查询暴露给外部 API——按标价，一个每天处理 1 万次查询的 Claude Opus 5.5 智能体年成本超过 7 万美元。LuthorSQL 是非自回归 7B 文本转 SQL 模型，单次前向在有界文法上预测查询计划的槽位得分，编译并执行最多 32 个候选计划，再由训练好的验证器选定答案，仅在不确定时升级给慢速智能体。单独运行时在 BIRD 隐藏测试集上达到 68.03% 执行准确率，单 GPU 每题 0.84 秒，8 位量化后 9GB 显存可维持精度，零样本迁移到 Snowflake、BigQuery、MySQL、PostgreSQL 和 DuckDB 时与原生 SQLite 精度差距在 3.1 个百分点内。与 Claude Opus 5.5 组成置信级联、在 Opus 训练截止后发布的数据库上测试 227 题，近半数问题本地解决，同等精度下 API 成本降低 33.3%。
  - 重要性：★★★★★ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.17780)

- **Interpreting Coding Agents 用 14 万条执行轨迹刻画智能体行为**：作者分析来自 125 种智能体配置、117 个不同模型共 143,209 条执行轨迹，并开发规则式解析器把原始执行记录映射为仓库搜索、文件编辑、测试执行等高层动作，再用六模型共识参考在 500 个事件上审计其预测。结果显示，解题率相近的智能体在探索、修改和验证代码的方式上可能差异显著。在不使用任务结果、token 数和工具名作为特征的情况下，聚合行为画像仍能跨不相交的仓库集合与编程语言检索出对应的智能体栈。对前沿模型与智能体脚手架的分析表明，脚手架选择和推理投入程度会系统性改变搜索、编辑与测试行为。作者发布确定性解析器、完整标注与分析流水线及标注轨迹子集，为从「是否解出」转向「如何解出」的评测提供基础设施。
  - 重要性：★★★★☆ / 5
  - 来源：[HuggingFace Papers](https://huggingface.co/papers/2611.17440)

- **WebArena-Pro 推出异构多模态可复现 Web 智能体基准**：现有可复现 Web 智能体基准只覆盖少数软件类别的少量应用，且模态限于文本与视觉；实时基准扩大站点覆盖却牺牲可复现性。WebArena-Pro 包含 300 个任务，横跨六个领域类别的 20 个自托管 Web 应用，覆盖不同界面约定、工作流与数据模型，并把音频和视频作为与文本、视觉并列的核心观测，配有专门的信息抽取动作。评测中 Codex 搭配 GPT 6.1 Sol 与 Claude Code 搭配 Claude Opus 5.5 并列最佳，均为 62.3%，OpenCode 搭配 Kimi 3.1 Pro 为 60.7%；最强的通用智能体配置 Gemini 3.1 Pro omni 与 Gemma4 31B 均为 30.3%。每个任务隔离运行，兼顾可复现性与多模态覆盖。
