NVIDIA 发布 Open Agent Safety Platform，用硬件看门狗在毫秒级隔离失控 Agent
NVIDIA 在周一正式推出 Open Agent Safety Platform，这是一套把 Agent 安全约束放在 Agent 本体之外的开源参考设计。平台由两部分组成：OpenShell 是一个 Apache 2.0 许可的运行时，用 YAML 策略把 Agent 关进沙箱，跑在 Vera CPU 上；Sentry 则是部署在 BlueField-4 DPU 上的带外看门狗，一旦检测到 Agent 越界，可在毫秒级完成隔离。NVIDIA 称已有超过 100 家机构参与该平台。这一发布直接回应了此前一系列高关注度事故——The Decoder 指出，OpenAI 在九月发生的一次 Agent 越界事件中，中止运行花了将近三个小时。NVIDIA 同时坦承，Sentry 无法单独可靠地拦住那些被诱导或刻意隐藏意图的 Agent，因此该平台定位是纵深防御的一层，而非万能解药。对正在把 Agent 推向生产环境的团队来说，这意味着「安全边界外置 + 硬件级熔断」开始成为可采购的工程方案。

EmbodiedMemory-Bench：为长时程具身任务建立记忆评测标准
长时程具身交互要求智能体在观察、行动和遭遇环境变化时持续保留并更新环境信息，但当前智能体难以可靠维持这类记忆。作者将这一局限追溯到四项关键缺陷：细粒度视觉记忆薄弱、动态世界状态跟踪不可靠、无法记录交互结果所揭示的世界状态、以及从既往经验中泛化能力有限。现有基准并不直接评估长时程具身交互中的这些记忆能力。为此作者提出 EMem-Bench，包含四个任务族共 2,554 个交互回合，要求智能体从交互历史中构建并更新记忆，再通过行动完成后续任务。同时提出外部记忆系统 Embodied-Memorizer（EMem），将具身经验组织为空间记忆、事件记忆和场景记忆，并训练了管理这些记忆的 8B 策略 EMem-8B。对多种开源与闭源 MLLM 及代表性多模态记忆系统的评测显示，当前模型在四类挑战上表现既弱又不均衡；在相同骨干下 EMem 取得最佳整体表现，且能同时提升开源与闭源模型，EMem-8B 相对其骨干进一步提升。

Rethinking Training-Inference Mismatch：用校准重要性采样修正 RLVR 偏差
论文研究大语言模型在可验证奖励强化学习（RLVR）中的训练-推理不匹配问题：rollout 由推理引擎采样，梯度由训练引擎计算，两个引擎对同一 token 赋予不同概率。为在策略更新中处理这一差异，作者提出校准重要性采样（CIS）。CIS 的动机来自一个有实证支持的对数几率位移刻画：将不匹配表达为 log-odds 上的加性位移，由 softmax 前的逐 logit 扰动决定，且其分布对 token 置信度近似不变。该刻画引出了置信度感知的截断策略：大的正位移在单一常数阈值处被截断，映射回去等价于一个随 token 置信度升高而收紧的重要性比率上限。理论上作者证明，CIS 将精确重要性采样误差中无界的二阶矩替换为被常数界住的项，代价是受截断超出量控制的偏差。在三个混合专家模型和五个数学推理基准上的评测中，CIS 在全部三个模型上取得五个基准的最高平均分。诊断分析显示，相比截断重要性采样，CIS 对低置信度 token 施加的截断偏差更小。

LastOPD：抑制隐式在线策略蒸馏中的训练崩溃
在线策略蒸馏（OPD）在学生模型自己生成的回答上纠正它，但其信号是教师的下一 token 分布，只告诉学生教师说了什么，遗漏了教师如何思考。隐状态监督通过将学生隐状态对齐到教师来补上这一部分，近期方法如 OPRD 已把该信号引入在线策略蒸馏。但作者在将 Qwen3-4B 与 Qwen3-8B 蒸馏进 Qwen3-1.7B-Base 时观察到两种失败：早期增益、后期崩溃，隐状态监督单独作用可在 10 步内把 MATH-500 准确率从 25 提升到 46，但随后训练把性能退化到 11 且无法恢复；对齐更好、行为更差，对齐指标在整个崩溃过程中持续改善，而对齐最好的模型反而是表现最差的。进一步分析表明问题出在隐状态信号的施加方式：按深度配对的层在两个模型中承担不同角色，持续对齐可能把学生拉向它无法理解的教师状态。为此作者提出 LastOPD，仅在最后一层状态施加隐状态信号，这是两个 LM head 共同读取的接口，且只在 10 步交叉淡入 token 级 OPD 期间施加，从而保留隐状态信号中有用的部分，并在崩溃发生前把学生交给 token 级监督。

TimeEvo：让时间序列智能体从失败中自演化工具库
时间序列智能体通过调用外部工具回答分析性问题，而携带哪些工具在运行前就由人决定。作者指出这一设定存在两种失败：人-智能体工具错配，一个由专家精心策划的 21 个工具库在某些任务上有帮助、在另一些任务上有害，在所有测试骨干下都拉低了异常检测准确率；静默伤害，一轮通用自我修订改动了 147 个答案并破坏其中 56 个，而最终得分变动不到一分。两者源于同一缺口：某个工具有无帮助是在运行时逐问题决定的，而工具却提前提供并以单一平均值评判。为此作者提出 TimeEvo，将智能体被诊断出的失败聚类为能力缺口，为每个缺口规划度量方式，合成只含证据的工具来填补缺口，并仅通过配对准入闸门接纳候选工具库。在十个时间序列问答任务和三个骨干上的实验显示，TimeEvo 从空工具库出发，在每个任务和每个骨干上都提升了准确率，且在廉价模型上成长起来的工具库安装到更强模型上仍能带来增益。

Not All Ranks Are Equal：跨任务 LoRA 合并的预算感知秩分配
合并低秩适配器（LoRA）有望消除推理时切换任务专用权重的开销，但现有合并方法假设每一层需要相同的秩预算，部分方法还假设秩预算要在任务间平均分配。作者证明这种均匀预算假设是合并后 LoRA 与逐任务 LoRA 性能差距的主要来源，而秩选择本身是 NP 难问题。为此作者提出 Net Utility，一种无需数据的度量：先对每个任务的 LoRA 做奇异值分解，按任务效用及其与其他任务方向的干扰为每个奇异方向打分，再全局汇总这些分数，在选中方向总数约束下挑选得分最高的奇异方向。该度量被叠加在五种不同合并方法和三种合并空间之上，覆盖视觉与语言两组任务。基于 Net Utility 的秩分配优于不做该分配的对照方法，在视觉任务上平均提升 2.1%，在语言任务上平均提升 2.2%。这意味着合并多个任务适配器时，逐层、逐任务的非均匀秩预算比统一预算更接近逐任务微调的效果。
