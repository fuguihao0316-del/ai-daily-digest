Meta 发布 Muse Spark Open：816B 参数、1M 上下文的美国最强开放权重模型
Meta 于 10 月 15 日发布 Muse Spark Open，采用 816B 总参数 / 42B 激活参数的 MoE 架构，上下文窗口达 100 万 token，原生支持文本、图像、视频、音频四种模态，定位是编码与 agentic 长程任务。工程侧配套动作很大：随模型发布自定义可自动调优的 Helion GPU kernels 并集成进 SGLang，在 NVIDIA 与 AMD GPU 上取得 1.03–3.95 倍 kernel 加速，AMD MI350 上端到端提升 3%；推理侧支持 SGLang、vLLM、TensorRT-LLM、Hugging Face Transformers、Apple MLX、llama.cpp 与 Unsloth。最受关注的是本地部署：Meta 称其可在两台搭载 M5 Ultra 的 Mac Studio 上通过最新 MLX 框架运行，这也是与 Apple 联合宣布的合作点。权重已在 Amazon SageMaker AI、Google Cloud Model Garden、Hugging Face、Microsoft Foundry Models 开放下载，Baseten、Fireworks AI、Groq、Modal、Nebius、OpenRouter、Together AI 同步提供 API。安全后训练在 Meta 的 Superintelligence Scaling Framework 下完成评估。

FreeSolo：零样本长度外推的线性时间稀疏注意力
线性时间序列模型通常把长上下文信息压缩进固定大小的循环状态，容量受限；而混合架构引入全注意力又会带来二次复杂度。FreeSolo 提出原生稀疏注意力机制，包含短程滑动窗口分支与长程分支，后者通过选取关键点单元直接对 token 做注意力。其线性时间变体 FS-L 经短程持续预训练学会在查询相关选择之前剪枝前缀；FS-B 则用基数排序构建平衡树搜索，算法代价为 O(Nlog²N)。实验显示，FreeSolo 在未做长上下文微调的情况下，零样本长度外推表现优于基线。对需要长文档与长视频推理的开发者而言，这提供了一条不依赖昂贵 CPT 的上下文扩展路径。
★★★★★

LayerTrim：无需训练的结构化剪枝保住长链推理能力
结构化剪枝通过移除模型组件得到更小的稠密模型来降低推理成本，但现有方法会让 AIME 这类长链推理任务的性能崩塌。LayerTrim 提出免训练的结构化剪枝方法，先识别冗余解码层，再选择性裁剪这些层的 MLP 特征，同时完整保留注意力和解码深度，是首个为保护长链推理而设计、不需要梯度或恢复训练的免训练剪枝方法。在三个推理语言模型和五个基准上，LayerTrim 多数设置下优于现有结构化剪枝方法，平均准确率较 RESP 最高提升 21.4 个百分点。在 Qwen3-14B 上实现 1.24 倍更快的 prefill 和 19.7% 的峰值 GPU 显存下降，同时平均生成长度最短、平均准确率最高。

NoteBank：用稀疏情节记忆把线性注意力的一百万 token 检索准确率从 1.7% 拉到 70.3%
线性注意力承诺了长上下文建模所需的效率，但其固定大小的循环状态必须同时承担持续计算与保存不断增长的历史信息，这种耦合强化了「状态记忆容量决定长上下文能力」的固有看法。NoteBank 挑战这一上限，提出稀疏情节记忆：在未知未来查询之前就归档选定文本，用骨干网络原生特征完成写入与寻址，并通过 replay 让检索到的证据经由原生前向计算读取。该接口免训练、即插即用，无需外部嵌入模型、单独训练的检索器或独立神经阅读器。在 100 万 token 规模上，它把 Gated DeltaNet 在六个 RULER 检索任务上的平均准确率从 1.7% 提升到 70.3%，4K 到 1M token 未见明显检索退化，仅增加不超过 0.025% 的分析 FLOPs，持久上下文存储约为同宽深精度下 Transformer 全 MHA KV cache 的 1/2600。

Cortex：用测量门控来演化与剪枝编码智能体的技能和规则
Claude Code 这类编码智能体会遵循开发者写的文本文件，包括项目文件、可自行选择打开的技能、以及读取匹配文件时自动加载的规则，这些文件被统称为智能体的 harness。开发者每次纠正智能体都会往里加内容，但一次成功说明不了什么，同一个智能体可能这次通过下次失败。Cortex 的做法是测试 harness 的改动而非信任它们：把开发者会话中的修正保存为可重放任务，找出反复出现的纠正，一次只写一条技能或规则，并且只有在带与不带它的重复运行显示净收益且没有任务明显变差时才保留。已有文本在删除前也经过同样测试，Cortex 既不添加也不删除智能体从未用过的文本。在 Claude Haiku 4.5 上的测试显示，它构建的 harness 让智能体更常遵守约定，比较区域保持不变，且没有增加每轮都读取的文本。

APEX-Harm：在共享专业工作空间中评估智能体安全
专业智能体越来越多地通过命令行界面和多种工具，在包含文件、消息和业务应用的共享工作空间中工作，这类环境产生的安全风险很难用放置在单一已知读取位置的攻击来刻画。APEX-Harm 是一个评估长时程智能体遭受提示与脚本注入的基准，任务覆盖金融、咨询和法律，每个任务包含 115 到 328 个文件，并通过 MCP 服务器暴露邮件、日历、聊天、文档、表格、PDF 和代码执行工具。基准包含六类攻击，覆盖静态与动态注入、任务特定脚本替换和攻击者提供的通用脚本，评估攻击成功率、暴露度和任务表现。在 12 个前沿模型各 180 个任务实例上，Opus 5 和 Sonnet 5 总体攻击成功率最低（8% 和 20%），但任务特定脚本替换与通用脚本攻击平均成功率仍高达 81-84% 和 73%；Gemini 3.8 Flash 任务得分最高（0.877），攻击成功率仍有 33%。这说明完成任务并不等于行为安全。

CameraVLM：9B 参数超越 GPT-6 Astra 与人类观众的相机运动理解
现代视觉语言模型能解视觉谜题、能跟随长达一小时的视频，但被问到相机是向左还是向右移动时，大多数表现不比抛硬币好。单独加入相机运动数据或几何表示都被尝试过，但都没能弥合差距。作者认为相机运动理解需要同时满足两个条件：表示必须把屏幕外的相机运动与屏幕上的光流动态耦合起来，而且必须由语言模型来解释，而不是训练成独立的姿态或深度估计器。CameraVLM 将运动状态表示与状态-语言对齐配对，相机 token 捕捉相机如何在屏幕外移动，光流 token 捕捉主体与背景如何在屏幕上移动，两阶段训练策略让语言始终在环，使二者与相机运动语义一起学习。仅 9B 参数，CameraVLM 在三个基准、20 多个基线上大幅超越所有开源及相机运动专用模型，并在 48 人参与的研究中追平或超过 GPT-6 Astra 与人类观众。
