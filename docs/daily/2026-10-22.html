Google Cloud 联合 Red Hat、IBM 发布 llm-d 1.0
Google Cloud 与 Red Hat、IBM 共同发布开源项目 llm-d 1.0，这是一套 Kubernetes 原生的分布式 LLM 推理栈。新版本加入多租户流量控制、零停机升级和 agent-aware 路由，可跨 vLLM、SGLang 以及 TPU、GPU 异构算力调度，并支持 cache-aware routing 以复用 KV 缓存、降低推理延迟。对自建推理集群的团队而言，这意味着不必再自行拼装调度层，可直接在 Kubernetes 上管理多框架、多租户的推理负载；对云厂商而言，推理栈的开源标准化会进一步压缩专有推理服务的溢价空间。值得注意的是，该项目同时覆盖 TPU 与 GPU，实际上把 Google 自家加速器纳入了与 NVIDIA 生态同一套调度抽象之下。

AEON：统一视频与3D世界模型
现有显式世界模拟分两条路：视频生成模型（如 Sora）外观逼真但缺 3D 一致性，3D 生成模型（如 Marble）几何一致却静态、不够真实。AEON 的关键是在文本或图像条件下的视频潜空间中生成可渲染的 4D 图形基元，具体为 4D Gaussian Splatting（4DGS），作为显式世界表示。做法上，先训练一个 4D 重建模型从单目视频同时预测 4DGS 与相机位姿，作为初始化 4D 解码器；再设计域适配器，在视频 VAE 上通过蒸馏把生成式视频潜变量转换为重建式 4D 潜变量。AEON 天然支持沿预测相机轨迹渲染 4DGS 的视频式世界建模，并能构建带场景动态的持久 4D 环境。作者称其在标准基准上取得 SOTA。对做世界模型与 4D 重建的读者，这条提供了一条把生成先验落到可渲染几何表示的可行路线，绕开了纯视频模型难以保持 3D 一致的老问题。

Not All Features Are Created Equal：VLA 策略的机制研究
一个微调后的 Vision-Language-Action 策略能按指令把字母汤放进篮子，但篮子左移五厘米它就把汤掉下桌。作者搭建可解释性流水线，发现把任务 A 的激活注入 action expert、同时让策略看任务 B 的场景，pi0.5 在 99.6% 的回合（n=1968）中执行任务 A 的运动轨迹。该注入程序绑定在绝对工作空间坐标上并忽略可见场景，这为同期基准报告的扰动脆弱性提供了机制解释。绑定在真实 UR10e 上同样成立：定向回放在一个方向上 26/26 次改写了指令任务，另一方向 18/26 次；无注入与随机方向对照处于地板水平；源物体移动 10–15 cm 后，机械臂在 50/50 次试验中按记录坐标抓放，有错块就抓错块，没有就抓空。对 LIBERO、MetaWorld、SimplerEnv、ALOHA 上六个 VLA 共 42 万+ 回合的同类干预还给出三点发现：所有架构都编码指令，但五个中有四个在场景本身足以确定目标时把视觉权重置于指令之上。对 VLA 鲁棒性研究，这是少见的因果级证据。

HarnessAdapt-RL：训练整个 agent 而不只是模型
训练编码 agent 通常只更新策略、固定 harness，但训练轨迹会暴露跨任务变化、并随策略演进而改变的修复策略缺陷与交互问题。HarnessAdapt-RL 在强化学习过程中同时训练策略并适配其 harness：对修复策略缺陷，用冻结教师生成任务特定的机制级技能；对跨任务复发的交互问题，由另一个教师模型演化工具与 hook，每项改动只有在提升观测通过率或可训练率且不降低另一项时才保留。策略在适配后的 harness 上训练，新轨迹再反过来指导适配。以 9B 基座模型，HarnessAdapt-RL 在 SWE-bench Verified、Multilingual、Pro 上分别比 GRPO 提升 pass@1 达 9.8、12.6、6.4 个百分点，并优于使用人工设计 OpenHands harness 的 GRPO。机制级技能带来的增益在其评估前移除后仍然保留；随策略变化持续重演化工具与 hook 优于冻结早期版本；而在部署时移除它们则损失最多 7.7 个百分点。结论是训练产出的是模型-harness 配对。
★★★★★

Self-Credit：用组内重标定为长程 agentic RL 做信用分配
LLM agent 常用 RLVR 训练，但奖励稀疏使信用分配在长程任务上尤为困难。Self-Credit 是端到端 agentic RL 方法，通过组内重标定从稀疏结果奖励中自生成密集监督。它基于分组式 RL，含三部分：rollout 期间策略模型生成带引用的摘要，指向包含关键证据的早期轮次，作为自生成信用；再用组内重标定精炼，比较同一 prompt 下成功与失败 rollout 中被引用的动作，利用组级一致与分歧剔除不应得的信用、强化关键动作的信用；最后用重标定后的信用权重更新被引用轮次的优势。在 BrowseComp-Plus 上，Self-Credit 相对基座模型在 Qwen3 8B 与 32B 上分别提升 37.0 与 36.2 分，并超过最强 agentic RL 基线 8.5 与 5.6 分；在 GAIA 上超最强基线 4.9 分，xBench-DeepSearch 上超 4.7 分。分析显示自生成信用能有效选取关键动作，且组内重标定（尤其在失败 rollout 上）跨模型规模都重要。

Épi：面向自主研究的持久自我改进 agent

Ask to Distill：为 on-policy 蒸馏学习合成数据
On-policy 蒸馏（OPD）用极少的训练问题就能成功，这支持把问题视为分布知识迁移载体的观点。问题是如何在拿不到正确答案的情况下评估新生成问题对蒸馏的价值、并学会生成更好的问题。Ask-to-Distill 把合成问题当作分布引出器，沿学生生成的轨迹优化教师监督所暴露的部分。一个学生初始化的合成器用问题价值的分布代理来优化，该代理由冻结的学生-教师对计算，无需参考答案、正确性奖励或逐候选学生更新；奖励结合教师-学生分歧与教师在学生候选支撑上的概率质量，并加长度与多样性控制。生成的问题经过滤去重形成仅含 prompt 的题库，用于标准 OPD。在数学推理、代码生成与 agentic 任务上，该方法相对未优化的学生生成 prompt 与 KL 过滤的真实问题提升了平均表现和教师差距恢复度，在评估设定中匹配或超过真实题库 OPD。信号分析显示优化后的问题能从更短的学生回答中引出更密集的监督与更多总信号。

ATEST：面向 LLM 推理的自适应资源感知测试时扩展
测试时扩展（TTS）通过采样多个答案提升 LLM 推理，但固定采样预算既忽略查询难度，也忽略 GPU 争用下推理能耗的变化。作者测得同一四样本查询在 GPU 负载上升时能耗最高增加 4.1 倍。ATEST 是资源感知 TTS 框架，联合考虑额外样本的期望价值与当前 GPU 成本。默认模式 ATEST-Online 无需离线校准：增量生成样本、估计多数答案稳定性、监控实时 GPU 状况并在线学习每步能耗成本以决定何时停止；ATEST-Calibrated 则用离线准确率与成本模型为每个查询选预算，适合负载稳定的部署。在 NVIDIA A100 上用 Phi-3-mini 于四个推理与问答数据集评估，并迁移到 NVIDIA L40S 与 Qwen2.5-3B。四个 A100 数据集上 ATEST-Online 每个查询都不超能耗预算，同时取得最高或统计持平的准确率，并随负载上升减少采样。高负载下 GSM8K 上它以零延迟取得 60.0% 准确率，而 ATEST-Calibrated 为 44.0% 准确率、42.4% 延迟率。
★★★★☆

On the Limits of Scale：视觉语言模型中的逆缩放
缩放律通常认为增大模型、数据与算力带来单调提升，作者给出系统性证据表明 VLM 在子任务层面存在逆缩放：同一模型族内更大模型在某些问题类别上反而不如更小模型。他们评估四个模型族的 19 个模型、八个多模态基准（九个评测切分），每个模型回答 29,386 题，共 558,334 次模型-问题评估。通过族内所有模型对的逐题成对分析，识别出 375 个子任务-模型对组合存在逆缩放，覆盖 4,342 个唯一查询——小模型答对而大模型答错，且这些模式在独立开发的架构间可复现。13 个子任务-数据集对在多个族系上均显示逆缩放，说明现象由任务驱动而非模型特定。受影响最重的领域包括多图空间推理、视觉感知与大学水平 STEM 知识，若干情形准确率差距超过 20 个百分点，而图表理解相对抗逆缩放。这挑战了「增大模型均匀提升多模态能力」的假设。
★★★★☆

受人类整合语言、感知与动作经验的能力启发，UniWALM 在单一共享表示中学习视频、动作与语言，每种模态既是条件信号也是监督目标。与把推理或视觉语言模型挂在视频-动作骨干上、分阶段运行的做法不同，UniWALM 把三种模态统一在单个 mixture-of-transformers 骨干内，各模态扩散头同步协同去噪，在与动作同一次前向中解码子任务与文本记忆，无需单独规划阶段；生成的语言在下一步被重新消费，形成语言即记忆的闭环，无需外部规划器或记忆库。为在更丰富目标下保持动作流可靠，作者提出 Flow Matching with Correction（FMC），教会模型从受扰动作轨迹中恢复，且不增加推理成本。UniWALM 在组合式抓放（MolmoSpaces）上稳定优于同骨干基线（如 FastWAM），在 RMBench 的记忆依赖子集上达到 34.5%，且不使用任何预训练语言或推理模型，超过配备关键帧的 Mem-0 的 28.5%。
