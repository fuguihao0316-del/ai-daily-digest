Anthropic IPO 路演披露多芯片战略，Mythos 三天把 Claude 移植到 AMD
Anthropic 昨日启动 IPO 路演，联合创始人 Tom Brown 在「算力路径」环节首次公开细节：Claude 的训练与推理已同时跑在 AWS Trainium、Google TPU、NVIDIA GPU 和 AMD GPU 四个芯片家族上，这一多芯片押注在早期被认为不值得，因为每个平台都要自建软件与推理栈。今年首次接入 AMD GPU 时，Anthropic 让内部模型 Mythos 自行尝试，三天完成移植且几乎无人工干预，Claude 几乎 100% 的 kernel 由模型移植或编写，而过去引入新芯片平台需要数十名工程师数月工作。Brown 称第二个算力优势来源是「算力乘数」的发现速度，关注物理容量与效率的乘积而非单一指标。对读者的含义是：模型厂商正把「自研模型优化异构硬件」变成压低成本、削弱 CUDA 依赖的常规手段。

Deletion Tuning：只删 0.05% 权重即可媲美全参微调
论文提出 Deletion Tuning，在 transformer 各层 gate projection 上学习一个二值掩码，通过将不到 0.05% 的权重置零来获得新能力，在 RLVR、监督微调与 on-policy 蒸馏三种后训练范式下均与全量微调（FFT）持平。两个直接收益：训练得到的掩码比对应 FFT checkpoint 小数百到数千倍；灾难性遗忘显著减轻，在强化学习设置下其先验任务准确率保持在基座水平附近，而 FFT、LoRA 与随机稀疏微调最多掉 5.4 分。作者用 stable rank、谱漂移与主权重重叠度分析 RL 下权重变化的几何结构，发现 Deletion Tuning 在三项指标上都最接近 FFT，为「掩码为何足够」提供了机制解释。对做后训练与持续学习的团队而言，这意味着更新载体可以极小，且可把「保留旧能力」从调参问题变成结构约束。

RoboRisk 与 LEASH：基础模型控机器人的安全缺口与拦截方案
论文发现用 GPT、Claude 等基础模型控制机器人存在严重安全风险，而全面安全评测仍缺失，于是提出 RoboRisk 基准，含 92 个模拟任务与 13 个真机任务，分为任务级拒答、计划修复、执行期危害、注入、序列记忆五类；此前基准最多覆盖其中两类，部分只评文本输出，而 RoboRisk 五类全覆盖且每个任务闭环执行。作者评测 GPT-6 Astra、GPT-6.1 Sol、GPT-6 Luna、Claude Opus 5.5、Gemini 4 Argon、Grok 4.7 六个前沿模型，普遍呈现高危害率，另评测 Dream API 与 PokeBot 的 RoboAPI 两个机器人专用接口。为此提出 Lease-Enforced Agentic Safety Harness（LEASH），借助决策模型（Jev 或 OpenAI 的 Decisions API）实现任务、动作与提交三道闸门，在视觉上下文中审查任务、每个动作及每个不可逆操作，可接入几乎任何智能体架构。

Sable：单卡 92.5 秒为 32B 模型 4096 token 推理生成逐位证明

等算力协议推翻稠密奖励结论：Monte-Carlo 过程奖励反落后 GRPO 14.3 分
论文指出 RLVR 中 GRPO 给解答的每个 token 相同信用，稠密过程奖励（如从中间步骤采样续写打分的 Monte-Carlo 奖励）被提出来给中间步骤分配信用，但以往比较按每次更新或单批次梯度检验，忽略了成本——在其设置中续写本身占全部生成 token 的 91%。作者提出匹配算力协议，以生成 token 数与训练 GPU 小时数为预算，在预注册研究中对六模型共 1,668 次运行做对照。结果算力对齐后排序反转：Qwen2.5-1.5B 上 Monte-Carlo 奖励每次更新领先标准 GRPO，但等 token 预算下最终低 14.3 个百分点、等训练时间下低 7.8 个百分点，四种稠密奖励变体无一在同等训练时间下胜过 GRPO；逐 token 梯度检验的排序与训练一致，但把每种奖励高估 1 至 2 分。相反，选择预测成功率最接近 1/2 的 prompt 训练在匹配算力下提升准确率，Qwen3-0.6B 上 +1.7 分、Qwen2.5-1.5B 上 +0.8 分。

Tree-Ising：把权重修复写成逐行 QUBO，MATH-500 上 54.6% 反超智能体编辑
