Anthropic IPO 路演视频披露多芯片训练策略
Anthropic 在 IPO 路演视频中首次系统披露其算力策略，联合创始人 Tom Brown 称 Claude 的训练与推理已同时跑在 AWS Trainium、Google TPU、NVIDIA GPU 和 AMD GPU 四个芯片家族上。这一多芯片押注在早期被普遍认为不值得投入，因为每类芯片都需要独立的软件与推理栈，成本高昂；如今 Anthropic 称已积累多年经验。最具体的案例是今年首次接入 AMD GPU：过去引入新芯片平台需要数十名工程师耗费数月，这次由内部系统 Mythos 尝试，仅用三天就让 Claude 在 AMD 上跑起来，几乎无人工干预，Claude 移植或编写了近 100% 的 kernel。Anthropic 称其算力优势的第二个来源是「算力乘数」的发现速度，关注物理容量与乘数相乘后的有效算力总量。对做推理部署与自建集群的团队而言，这意味着多芯片异构调度正从研究课题变成可复用的工程能力。

Google 开源 TPU Sync，KV cache 传输延迟降低逾 90%
Google 发布 TPU Sync，一个开源 C++ 库，用于在 TPU 的 HBM、主机 DRAM、存储和网络之间搬运 KV cache 与模型权重。Google 报告在 235B 至 480B 的 MoE 模型上，KV 传输延迟降低超过 90%。KV cache 的搬迁效率直接决定前缀缓存复用、PD 分离和跨节点扩缩容的可行性，此前这类工作多依赖各家自研的内部组件。以开源形式放出，意味着自建 TPU 推理栈的团队不必从零实现这部分基础设施，也降低了在 MoE 大模型上做长上下文服务的显存压力。对同时维护 GPU 与 TPU 两条推理路径的团队，这是一个可对照参考的实现。

MixUA 让多用户多智能体记忆按受益范围分级

PixVid 把潜空间视频扩散「提」回像素空间

控制实验拆解多模态视觉编码的三个设计选择
多数多模态模型沿用预训练视觉编码器，近期也有与语言模型联合从零训练甚至完全去掉编码器的做法，但公开模型在数据、架构与算力上各不相同，无法隔离单一选择的影响。该工作在同一数据上从零预训练全部模型，并在匹配生命周期算力下比较视觉问答与语言基准。结论是视觉先验并非必需：联合从零训练的编码器与预训练编码器表现相当，且省去独立训练阶段；真正重要的是专用视觉容量——无编码器模型即便把主干扩大相应参数量仍在视觉理解上落后；但这份容量不必置于多模态融合之前，在早期主干层融合时加入纯视觉模块可与前置编码器相当，并降低首 token 时延。结论在多种主干规模、把编码器预训练视为免费、以及从预训练语言模型出发时均成立。
