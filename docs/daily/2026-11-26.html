GLM-5.4 采用首个 Loop Transformer 架构
中国 AI 实验室 Z.ai 发布 GLM-5.4，这是其首个采用 looped transformer 架构的模型。与传统 Transformer 每层在前向传播中只运行一次不同，Loop Transformer 让一组权重共享的层多次迭代运行，从而在不增加参数量的前提下加深网络、精炼隐藏状态。这已是本周内第二次出现 looped transformer 动向——11 月 20 日 Thinking Machines Lab 的 Inkling 2 Mini 同样采用该架构，其中间层对每个 token 运行三次，以更少 token 完成推理密集型任务如 agentic coding。GLM-5.4 目前尚未开放权重，Z.ai 表示将在完成必要的安全加固后负责任地开源。该模型暂不能通过常规 API 访问，需订阅 Coding Plan；两者共用 OpenAI 兼容的 Responses API（https://api.z.ai/api/v1 ），Coding Plan 的 API key 可直接调用新模型。Simon Willison 为此构建了 llm-glm 插件进行实测。

OpenAI 与 Cisco 开源 Shirudo：让 agent 在运行中防御系统

CONCOR：把对比解码的纠错能力本身单独拿出来评测
现有多模态大模型的对比解码（CD）评测几乎都只看最终任务分数，而候选过滤、生成轨迹漂移和回答偏好会混淆分数，使底层对比调整的真实效果无法被单独观测。为此作者提出 CONCOR（Contrastive Correction Evaluation）受控基准，用 Contrastive Grounding Margin（CGM）直接度量真实答案与各类幻觉候选之间的竞争关系，并进一步分析对比修正的方向一致性、构成与可靠性。评测显示现有 CD 方法行为明显分化：一部分稳定偏向真实候选，另一部分修正力度强但同时引入更多错误；这恰好解释了为何增大对比强度会让某些方法变好、另一些反而退化。对做幻觉缓解的研究者而言，这意味着调参时应评估修正机制本身而非只看最终输出，CONCOR 提供了可解释的对照框架。

作者发布 OWE-Bench（OpenWorldEngineer-Bench），由软件工程、物理工程、机器学习和科学计算领域的专家撰写 26 个长周期任务，涵盖内核优化、飞机设计到地震断层归因，单任务平均消耗数亿 token。评分同时看速度、成本、准确率，并区分智能体可自测的给定用例与任务描述隐含的隐藏用例。当前最强模型 Claude Fable 5.2 得分 54.6%，单任务平均 211M token。两个发现值得注意：给更多时间时模型会用更多测试时算力并提分，但扩展方式不同，GPT-6 Astra 在更短时限与同等 token 下得分更高，Claude Fable 5.2 靠更长时限消耗更多 token 拿到最高总分；所有模型在隐藏用例上平均低 18 分，即部署落差，且模型普遍高估自己在隐藏用例上的表现约 21 分。

SpatialArena：52 个几何基础模型在同一把尺子上重排

Model Carving：让训练过程自己削出 Transformer 拓扑
传统 Transformer 在每一层都训练固定顺序的注意力与 MLP 子层，这种齐整性只是惯例而非原则性设计。Model Carving 给每个子层加可学习标量门，让训练损失在单次训练中自行移除组件，从而在内部释放出一个更小的异构网络。作者预训练 140M 到 2.7B 的标准 Transformer 以及 140M 到 1.3B 的循环 Transformer：同等训练算力下，carved 模型验证损失低于用最多 1.7 倍算力训练的稠密模型，且优于同尺寸的剪枝或蒸馏产物。作者据此主张，为边缘设备获得小模型的最佳方式是在训练中直接削出，而非事后压缩大模型；该优势随规模增大而扩大，并延续到 few-shot 评测与生成等下游任务。

DyLoMo-DiT：复用参数而非堆参数，FID 最多降 56%
扩散 Transformer 靠同时增加参数量与计算量扩容，MoE 变体虽扩大参数容量但每 token 计算近似固定，仍需大量参数存储。DyLoMo-DiT 选择复用参数：权重共享的循环反复施加中间层，稀疏专家按 token 分配参数容量，从而在不加参数的情况下加深网络，把参数预算让给更多专家或更多独立层，并按噪声水平动态分配计算遍数。实验显示它更有效地利用参数与计算预算，把更多遍数分给低噪声步还能再涨。ImageNet 256×256 上，在匹配参数与计算预算时，相对 DiT 降低 FID 11-24%，相对 DiT-MoE 降低 36-56%。文生图方面，放大的 DyLoMo-DiT 在 GenEval 上得 0.714，高于 FLUX.1 的 0.673，而激活参数不到其十分之一（1.05B 对 12B）。
