Sakana AI 发布 Namazu Small：30B 模型在 25 项基准上反超 120B
Sakana AI 于 11 月 26 日发布 Sakana Namazu Small，这是一个基于 NVIDIA Nemotron 3 Nano 构建的 30B-A3B 推理模型，采用 MoE 架构、激活参数约 3B。官方口径称其在 25 项基准上平均得分 60.1，高于参数量四倍的 Nemotron 3 Super 的 56.2，也就是说小模型在综合评测上压过了大模型。这条消息的关键不在单点分数，而在于它延续了 2026 年一个清晰的工程趋势：以 Nemotron 这类开放基座做二次训练，用更少的激活参数换取推理成本优势，同时把性能差距压缩到可接受范围。对做推理部署的团队来说，30B-A3B 意味着单卡或双卡即可承载的显存占用和更低的每 token 成本，是替代 100B 级别稠密模型的现实选项；对做模型定制的团队来说，基于开放基座的日本主权模型路线也提供了可复制的样本。需要留意的是，60.1 与 56.2 的差距仅约 4 分，基准集合的构成会显著影响排名，实际业务表现仍需自行验证。

OpenAI 与 Cisco 开源 Shirudo：让 agent 在系统运行中部署防护
OpenAI 与 Cisco 于 11 月 24 日发布 Shirudo，这是一个 BSD 许可的预发布 eBPF 运行时，面向 Linux。其机制是让 AI agent 编写带签名的「shield」，在运行中的系统上阻断漏洞利用路径，从而为团队测试和 rollout 真正的补丁争取时间窗口，避免传统打补丁必须停机或重启的代价。这条消息值得关注的点有两个：一是 agent 的输出从文本、代码延伸到了内核层面的可执行安全策略，且用签名机制约束 agent 的权限边界，这是 agent 落地高权限场景的一种工程范式；二是 eBPF 让策略可以动态加载而不中断业务，契合生产环境的可用性要求。对安全与平台工程团队，这意味着漏洞响应流程可能从「排期打补丁」变为「先由 agent 生成临时 shield、再验证修复」，但也带来策略误伤、签名密钥管理和审计追溯的新问题。预发布状态说明 API 与行为仍可能变化。
