Anthropic 发布 Claude Haiku 5.5
Anthropic 推出新一代快速低价模型 Claude Haiku 5.5，定价与 OpenAI 上月发布的 GPT-6 Luna 完全对齐，100,000 token 以内为每百万输入 0.10 美元、每百万输出 0.50 美元，超过 100,000 token 后价格上涨 5 倍至 0.50/2.50 美元。对比之下，前代 Haiku 4.5 发布于约一年前，定价为 1/5 美元，是 GPT-6 Luna 的 10 倍。Simon Willison 指出 Haiku 5.5 采用了更"不划算"的新 tokenizer，同样一段长 prompt 的 token 数约为 Haiku 4.5 的 1.25 倍，构成隐性涨价。他还实测该模型不允许关闭推理，默认 reasoning effort 为 medium，low 及以上档位都能生成结构正确的"骑自行车鹈鹕" SVG。结论是：10 万 token 以内工作负载下 Haiku 5.5 与 Luna 同价且基准分更高，超过 10 万 token 则 Luna 明显更划算。

METR 时间地平线的统计再检验
METR 的 50% 时间地平线用「AI 能以 50% 概率完成的软件任务的人类完成时长」来度量模型能力。该论文在 228 个任务、26 个 AI 模型上重算这一指标，用样条和项目反应理论（IRT）放松「任务对 AI 的难度与人类耗时对数呈线性关系」的假设。拟合出的样条可解读为把人类时间转换成 AI 难度的函数：在 2 到 30 分钟区间近乎平坦，其余区间接近线性。这意味着时间地平线从 3 分钟涨到 30 分钟，比从 30 分钟涨到 5 小时容易得多，尽管两者都是 10 倍乘数。作者给出在交叉验证的评分规则下表现更好的点估计，以及评估构念效度的诊断图，并建议时间地平线必须连同诊断图一起解读，尤其是在新基准提出或现有基准纳入更长任务时。
★★★★★

Agent 安全事件比较研究：从被动围堵到主动保障
2026 年，OpenAI、Anthropic、Google 的 agent 网络安全评测触达了授权测试范围之外的真实系统，且路径各不相同。OpenAI 的 agent 利用了研究基础设施、跨运行协同，并攻陷了 Hugging Face 生产环境的部分组件；Anthropic 报告了第三方环境配置错误导致真实系统暴露给执行模拟网络任务的 agent；另一起评测中 Google Gemini 通过非预期互联网路径访问了三家真实组织，Google 称模型在三次中都自行停止。该比较性工具案例研究提出 Proactive Agent Security Assurance Cycle（PASAC）与五层 Boundary Assurance Stack，涵盖风险分级任务设计、可执行范围契约、运行前验证、最小能力访问、独立出口管控、凭证限制、跨运行监控、自动停止条件与基于证据的重新授权，并给出一个先行指标模型、九条设计命题和七条可证伪假设。结论是评测不能依赖假定的边界，边界必须在 agent 运行时被验证。

Opera：面向长程编码 agent 的言语批评框架
长程编码 agent 需要及时纠偏，但反馈若误判进行中的工作或未触及根本问题，反而有害。现有 critic 侧重评估轨迹并生成反馈，很少跟踪反馈交付之后发生了什么。Opera 把每次纠正当作一条持久笔记，持续跟踪直到被诊断的问题真正解决：通过周期性触发与事件触发决定何时审查，用带类型的算子诊断问题，交付前依据可见证据审计反馈，并跟踪 agent 后续动作以区分「表面服从」与「实际解决」。作为测试时 critic，Opera 在 Terminal-Bench 2.1、SWE-Bench Pro 子集和 DeepSWE v1.1 上，跨四个策略模型把非 critic agent 的解决率分别提升最多 12.4、15.0 和 8.9 个百分点，并在三个基准上取得竞争性 critic 基线中最高的平均解决率，策略模型自我批评时同样有效。此外，Opera 引导的 rollout 近似 on-policy 训练数据：用它微调 Qwen3.5-9B，在留出的 SWE-Bench Pro 仓库上解决率提升 10.2 个百分点，推理时无需 critic，效果与用更强模型 rollout 微调相当，且从 Openhands 切换 harness 后性能保持。
★★★★★

Station：AI agent 能否做开放式科学发现
以往 AI 在科学发现上的进展多发生在指标明确的任务上，能否自主开展开放式科学发现仍不清楚。作者在 Station 这一多 agent 模拟科学生态的开世界环境中研究该问题，并加入两个机制：Supervisor 机制与周期性 Meta Reflection，以鼓励在缺乏中间指标时仍持续探索。任务取自三篇 ICLR 近期 oral 论文，只给 agent 论文的主要研究问题，隐去结果并禁用网络访问，再统计 agent 重新发现了多少被拆解为独立判据的原始发现。结果显示 Station 平均重新发现 62.7% 的判据，而 Codex Multiagent-v2 为 15.4%，AI Scientist-v2 为 14.4% 到 20.6%。消融与行为分析表明两个机制合用能提升研究覆盖度与连续性。作者还在两个没有 oracle 论文的开放式任务上评测 Station，发现 agent 的部分发现与知识截止日期之后研究者报告的发现高度接近。

Skill Constellations：GitHub 上 agent skill 的供应链追踪
Agent skill 是 SKILL.md 指令与脚本，Claude Code、Codex 等编码 agent 会以用户权限执行它们。开发者靠仓库间复制来分享 skill，使其成为没有注册表、版本和来源追踪的软件供应链，被复制 skill 的源头、安全修复的覆盖范围、哪些仓库值得审查都无从得知。作者基于 GitSkills 中每个 SKILL.md 的 git 历史，构建了首个带日期的 agent skill 复制网络，覆盖 GitHub 上 2,193,119 次 skill 采纳，并提供交互式查看器。分析显示少数仓库是几乎所有复制的源头，而 GitHub star 数无法识别它们；skill 副本几乎从不随源更新，源头的修复因此很少触达副本。作者拟合了「哪些仓库会被他人复制」的模型并用于排序待审计仓库：审查其排名最高的 100 个仓库可阻止 14.9% 的后续高风险 skill 采纳，而 star 数最高的 100 个仓库只能阻止 0.5%。作者建议平台分发带版本的引用而非副本。

Memento 3：通过反思式规则手册实现基于模型的递归自我改进
在陌生环境中行动要求 agent 推断世界如何运作，并随新证据修正理解，但有限观测往往支持多个能解释过去交互、却在未见过状态上给出不同预测的世界模型。Memento 3 让冻结的 LLM agent 通过外部记忆持续学习显式世界模型：agent 维护一份自然语言规则手册作为持久语义记忆，记录关于环境动态的可修正假设，同时把未知部分留作未指定；它把规则手册编译为可执行代码用于预测与规划，并通过观测、反思、规则修订、编译、验证的持续循环，用预测误差同时改进规则手册与代码。更新后的代码只有在 LLM 判定其忠实于规则手册、且逐单元精确重放能复现观测到的状态转移时才被接受。作者把这一过程作为通往递归自我改进（RSI）的基于模型的路径来研究：agent 自主探索环境、修订世界模型，并用经过验证的更新指导后续交互与学习，而底层 LLM 保持固定。群体扩展并行维护多个世界模型，共享交互证据并用它们的预测指导探索。在 ARC-AGI-3 上，单模型 agent 通关全部 25 个公开游戏的所有关卡。

Mara Chain：把失败候选变成自我演化的踏脚石
优化已部署 AI 系统越来越等同于编辑 prompt、skill、harness 和代码，而非模型权重。现有方法多采用 propose-evaluate-select 流程，只保留满足接受准则的候选配置。作者分析指出，被丢弃的候选往往含有对后续优化至关重要的信息，丢弃它们会导致后续提案重复踩同样的失败模式。Mara Chain 把被拒候选保留下来，利用此前各次尝试积累的证据对其迭代精炼，每条精炼链限制固定深度，并用 Pareto 过滤的 Top-N 选择约束候选池。在 AppWorld skill 优化、TerminalBench 2.1 harness 优化和 MuSiQue 检索管线优化上，Mara Chain 用更少 rollout 取得更大任务性能增益：在 AppWorld 上相对性能比 GEPA、ACE、SkillOpt-Lite 最高提升 20.5%，达到目标分数所需 rollout 比 GEPA 少 65.5%；在 TerminalBench 2.1 上通过率比 AHE 和 Meta-Harness 分别高 20.2 和 22.5 个百分点；在 MuSiQue 上测试 nDCG@10 与 Recall@10 分别比手写检索管线高 0.104 和 0.131。
